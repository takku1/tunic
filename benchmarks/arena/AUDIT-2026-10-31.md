# Arena measurement audit — 2026-10-31 (HEAD 327f9ba)

External audit of Tunic's metrics at the semantic-baseline commit. Verdict:
enough data for a useful initial baseline, not yet enough to judge against
Graphiti/Mem0/Cognee or to confirm retrieval changes improve quality.
BM25 beats semantic/hybrid arms on F1 despite their higher recall.

## Metric coverage at audit time

Present: precision/recall/F1 micro-aggregates, per-task TP/FP/FN, exact-task
success (separate from agent success), mean/max/per-task latency, cache
hits/misses (212/28), full model identity, retrieval provenance via stages.
Missing: Recall@k / Precision@k, MRR, nDCG, p50/p95/p99, cold/warm split,
ingestion and index-build cost, peak RAM/disk/CPU, context tokens and
evidence density, citation correctness in-run, abstention calibration
(threshold sweep, negative suite), unified refresh performance, statistical
uncertainty, comparable competitor runs.

## Three immediate fixes (accepted, in order)

A. Benchmark measures set membership, not ranking. Five candidates per task
   on tiny fixtures lets 100% recall hide bad ranking. Add Recall@1/@3, MRR,
   nDCG@5 immediately.
B. Cold/warm latency not comparable. Separate cold-model+cold-cache,
   warm-model+cold-cache, warm+warm, and post-restart runs; percentiles only
   where sample counts support them.
C. Cache needs production tests: batch the SQLite IN query (variable limit),
   count every requested occurrence with duplicates, validate vector
   dimensions, handle corrupt entries, integrity tests. Also verify the real
   effective embedding context limit (manifest lists 2048 with num_ctx 8192
   override — confirm, don't assume).

## Permanent scoreboard families and instrumentation estimates

Retrieval quality 50% (P@k, R@k, MRR, nDCG, F1, exact success) · evidence
integrity 25% (edge precision, citation validity, contradiction handling,
unauthorized evidence) · temporal 15% (stale-answer rate, update visibility,
supersession) · performance 35% (p50/p95/p99, throughput, cold/warm,
ingestion) · resource efficiency 20% (RAM, CPU, disk, embed calls, tokens,
cost) · agent effectiveness 20% (multi-session success, context usefulness,
regression rate). Estimates are qualitative coverage judgments.

## Run-schema rule (binding)

Every arena run captures identity (commit, benchmark+digest, competitor and
adapter versions, model digest), conditions (hardware, OS, Python, runtime
settings, top-k, thresholds, budgets, cache state), results (raw ranked
candidates, labels, scores, evidence refs, abstentions, errors), timing
(ingestion, embedding, retrieval, traversal, qualification, compilation,
end-to-end), resources (peak RSS, disk, CPU, embed requests, tokens/cost),
statistics (trials, mean, percentiles, paired deltas, CIs where justified).
Crucially: capture pre-qualification AND post-qualification candidate sets,
so an improvement is attributable to discovery or filtering — never to
aggressive hiding. Never reduce to one leaderboard number; keep quality,
speed, cost, and reliability rankings with explicit trade-off rules.

## Implementation order (accepted)

1. Extend the semantic runner (ranked metrics, negatives, cold/warm,
   full environment manifest). 2. Qualification gate preserving raw
   candidate recall. 3. Rerun frozen benchmarks, paired before/after.
4. Performance/resource instrumentation in the same schema. 5. One real
   external competitor on a comparable retrieval task. 6. Roadmap resumes
   with arena as regression gate. Acceptance: precision and F1 above the
   hybrid baseline without losing the two OOV discoveries, evidence graph
   free of unsupported relationships. Do not optimize F1 by hiding valid
   difficult answers — Recall@k and per-category results must expose it.
