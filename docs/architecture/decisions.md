# Tunic design decisions and open choices

Status: design record, 2026-10-31. This is the authoritative list of decision dispositions. It is not an implementation completion tracker. “Working” means a reversible proposal adopted for consistent design/evaluation; it does not imply user approval of an irreversible dependency or demonstrated benefit.

| ID | Question | Disposition | Rationale and revisit condition |
| --- | --- | --- | --- |
| D-01 | Product identity | Settled by user: **Tunic** | GraphGraph remains a historical reference name. |
| D-02 | Compatibility with GraphGraph | Settled by user: not required | Preserve useful evidence and lessons; retain code/contracts only when independently justified. |
| D-03 | System boundary | Working: semantic graph, context compiler, runtime adapter | Logical owners, not separate mandatory services. Revisit deployment boundaries after measurement. |
| D-04 | Compiler output | Working: model-independent typed context IR | Separate evidence meaning from rendering/execution. Compare against direct rendering in G/T arms. |
| D-05 | First comparison | Working: W1 code impact, W2 temporal decisions, W3 task resumption | W1 is the proposed first vertical slice; later suites remain planned. Dataset/model/resource choices are open. |
| D-06 | Initial evidence policy | Working: source-faithful excerpts and explicit structured assertions/derivations | No silent summarization or premise loss. Add lossy transforms only as separately scored interventions. |
| D-07 | Initial update correctness | Working: atomic publication and full recomputation oracle | Conservative invalidation is acceptable. Narrower reuse needs an independence argument and differential checks. |
| D-08 | Geometry | Working: optional derived measurement view | Structural/learned scores never become source authority. Promote a feature only after its quality/cost ablation. |
| D-09 | Runtime reuse | Working: ordinary prefill; exact compatible prefix reuse when supported | No arbitrary cross-model KV/latent portability. Fusion/compression/custom attention remain experiments. |
| D-10 | Representation and persistence | SQLite selected for the user-authorized W1 reference; production choice open | The [reference profile](w1-reference.md) uses relational/adjacency tables and atomic full snapshots. Compare alternatives against actual queries and updates before a production commitment. No RDF/property-graph conformance is established. |
| D-11 | Language and process layout | Python selected for the user-authorized W1 reference; production layout open | Standard-library local implementation first. Choose later deployment boundaries from constraints and profiling. |
| D-12 | Model/runtime/hardware | Pinned local Ollama reference profiles selected; production choice open | [Continuation profile](continuation-reference.md) supports installed Llama 3.2/dense Qwen3 with explicit raw templates and input counting probes. [Smoke results](../evaluation/continuation-results.md) identify tested model/server/hardware; no general backend recommendation. |
| D-13 | Ontology and extraction profile | Bounded Python `static_call` plus document mentions, typed claims, and proposals reference profile selected; broader ontology open | [W1 profile](w1-reference.md) defines identities, byte evidence, coverage and static-path meaning. Mentions and claims link prose to code and doc entities; bare names propose with corroboration instead of merging. No automatic schema induction, NLP relation extraction, or general entailment engine. |
| D-19 | Temporal selection | Working bounded: valid-time `effective`/`authority` qualifiers, `timeline` query with `at` cutoff, supersession marking, conflict surfacing | Qualifiers are asserted text, not verified history. Superseded and future-dated entries filter out of views without deletion. Authority ranking, backdated corrections, and transaction-time replay beyond snapshots remain open. |
| D-20 | Conflict-aware retrieval | Working bounded: `transparent`, `evidence_only`, and `current` traversal policies; held-out memory suite with oracle-recorded outcomes | Policies select the traversal set, never rewrite stored evidence. `current` excludes superseded entities as of the snapshot date. The memory suite labels its oracle as teacher input. No autonomous conflict resolution. |
| D-21 | Hybrid task retrieval and agent evaluation | Working bounded: `answer()` stages exact keys, bare names, then BM25 chunk rank (`mode="graph"` preserves name-only); agent suite compares none/lexical/tunic | Lexical hits select candidates only, never graph edges. Dense retrieval now exists (see D-30): BM25 still leads on F1 (0.61 vs hybrid 0.41) while hybrid leads on Recall@1/MRR — ranking vs selectivity gap is the open problem. No semantic understanding is claimed. |
| D-22 | Structured acquisition review and promotion | Working bounded: `review` separates observations, assertions, name proposals, novel drafts, and contradicts-blocked pairs; `promote` records one exact-key claim, refusing duplicates and blocked pairs | Review is read-only; promotion writes a claim block that a later ingest publishes. Corrections stay explicit: a contradicts/supersedes claim must precede promoting over a dispute. No automatic assertion. |
| D-23 | Incremental graph maintenance | Working: file-level code-subset `refresh` reuses unchanged code extraction and reprocesses only affected documents; snapshot and retrieval behavior equal a fresh rebuild | Differentially tested on synthetic trees and PyQuifer (119/120 parses skipped, 1.5x wall time on a doc-heavy tree). Qualification inputs stay corpus-global in both paths; a requalification flip-check reprocesses documents whose kept mentions change verdicts. |
| D-24 | Multi-session agent evaluation with staleness | Working bounded: agent suite v2 over two fixtures; tunic arm answers under policy `current`; `answer` accepts `policy`; `compile_impact` blocks superseded entities including the queried symbol | The guard that exempted the queried symbol from blocking is removed: under `current`, a superseded node has no current dependents. Disputes stay visible (transparent and evidence carry them); staleness is excluded, not resolved. Latency and context size are measured per task; no tokens are claimed without a model call. |
| D-25 | Self-receiver resolution fix and real-repo validation | Working: `self`/`cls` heads bypass the local-shadowing guard (profile `python-static-v7`); validated against PyQuifer (120 files): self-call recall repaired, subscript receivers and torch `__call__` remain out of profile | The outer `head not in local` guard made the designed self-branch unreachable because `self` is always a parameter. Real-repo misses are documented limits, not regressions: indexed receivers, dynamic dispatch, decorator-replaced callables. |
| D-26 | Hybrid retrieval architecture | Working: staged exact/name/lexical/semantic candidates, weighted RRF fusion (k=60, priority weights), per-stage budgets, fused-score threshold, abstention on empty fusion; `EmbeddingProvider` with an Ollama backend on pinned `nomic-embed-text` (digest + config in `benchmarks/arena/models.json`) and a persistent digest-keyed vector cache | Semantic discovery proposes candidates only and never creates edges. Four-arm frozen baseline executed: recall 1.0 for dense arms but F1 0.41 vs BM25 0.61. No model is ever downloaded automatically. |
| D-27 | Evidence precision gate | Working: candidate index (lexical/semantic/name, broad recall) separated from the evidence graph (qualified relationships only); unqualified matches persist as reviewable `mention_candidate` diagnostics | Corpus-relative document frequency plus structural corroboration, never a stopword list. Frozen MochiOS negatives: FP 1.0 → 0.0 with zero exact references harmed. Pre/post-qualification sets are both recorded so discovery and filtering gains stay separable. |
| D-28 | Arena discipline and scoreboard policy | Working: frozen inputs/labels with corpus manifests and drift detection; tool rows only for executed runs, out-of-scope named with reason, never fabricated | Runner v2 records Recall@k/MRR/nDCG, cold/warm phases, threshold sweeps, and resources. Held-out splits are never tuned against. No single leaderboard number: quality, speed, cost, and reliability rank separately. |
| D-29 | Structural qualification signals | Working: `class_context` (frequency-independent), `module_path_context` and `inventory_list` (low-frequency only) join `dotted_or_call` in the qualification rule | MochiOS 0 FP held on all strata; PyQuifer dev `refers` recall 0.30 → 0.80 with 0/28 `not-a-mention` FP. `pyquifer-corpus-v1.manifest.json` frozen after byte-offset drift was found in the live checkout; links match by line number. |
| D-30 | Pinned local embeddings | Working bounded: single user-approved pull `nomic-embed-text`; model digest, config, and runtime pinned; digest-keyed persistent cache (source/model/chunking/preprocessing) | Cache keys include every input the vectors depend on; batching and duplicate handling covered by tests. No further downloads without approval, no paid APIs. |
| D-32 | Temporal correctness | Working: bitemporal timeline (`effective` valid + `recorded` transaction time), `corrects` vs `supersedes`, supports-minus-retractions arithmetic, `compile_history` per-snapshot replay; schema v2 | Supports survive independently; last retraction removes the edge while history is retained. Backdated corrections block under `current` and report as corrections. `record_outcome` accepts `retract` for `retracts` only. 10 temporal tests green; full suite 163 green with W1/memory/agent gates. |
| D-31 | Knowledge policy and selection contracts | Working design, partial enforcement: [policy contract](policy-contract.md) (five versioned decisions with reasons and receipts), [graph schema](graph-schema.md) v2, [evidence selection](evidence-selection.md) v1 target | Policy constrains retrieval, never hides inside a score. Selection layer is implemented as opt-in (`select=True`): adopt as default only on frozen-suite wins (see its acceptance clause). Research inputs: [policy survey](../research/knowledge-policy-survey.md), [standards mapping](../research/standards-mapping.md). |
| D-14 | Causal/discovery execution | Deferred | Hypotheses/constraints/transformations may be represented; execution and broad causal identification require a real harness and explicit assumptions. |
| D-15 | Integrations and federation | Deferred | Wilderbeast, Chili Crisp, and Team Ops are potential partners. No current interface compatibility is verified or required for the first slice. |
| D-16 | Numeric acceptance targets | Working provisional (framework v1 approved 2026-11-02; standings live in [implementation status](implementation-status.md#d-16-numeric-acceptance-targets-proposed-2026-11-02-provisional)) | Framework versions HELD / PASS-scoped / PROVISIONAL / BLOCKED / OPEN standings. Numeric targets themselves stay open until measured; no imported paper speedup is a Tunic target. |
| D-17 | Runtime-mediated memory | Bounded local segment implementation; broader extension experimental | [Controller](runtime-memory.md) now has a [local segment reference](continuation-reference.md); bounded prefetch remains proposed. Exact prefix reuse is orthogonal. Non-prefix fusion/learned bridges require distinct quality and graph-use tests; arbitrary mid-layer injection is not adopted. |
| D-18 | Evidence/runtime security | Working external requirements; shared/privileged deployment conditional | [Security](security.md) requires authorization before speculative reads and at attachment, trusted framing and independent tool policy. The local continuation profile implements bounded framing/profile checks and answer support; authorization, tools and shared isolation remain absent. Attention masks, provenance weights and token stripping are not security boundaries. |
| D-33 | Ingestion admission | Working: default-accept coverage ladder replaces per-type allowlists ([ingestion](ingestion.md)). Missing knowledge costs a rung, never the file; refusals are ledgered with a reason; credentials are refused in every family; symbols never imply edges; retrieval over new material is additive until a joint ranking passes acceptance. |

## Authority and changes

Component contracts live in [semantic graph](semantic-graph.md), [graph schema](graph-schema.md), [evidence selection](evidence-selection.md), [policy contract](policy-contract.md), [context IR](context-ir.md), [runtime](runtime.md), and [measurements](measurements.md). [Overview](overview.md) owns boundaries and flow; [workloads](../evaluation/workloads.md) owns comparison arms and task definitions. Research notes supply alternatives and evidence, not competing requirements.

When evidence changes a working choice, update this record and the owning contract together. Keep the source/measurement qualification in research. A feature becomes implemented only through actual code/check evidence; the [W1 profile](w1-reference.md) records the bounded implementation and executed checks. Target contracts must not be mistaken for completed capabilities.
