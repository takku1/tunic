# Faithful rendering and continuation reference

Status: implemented bounded profile extending [W1](w1-reference.md), [lowering](runtime.md), and the [runtime controller](runtime-memory.md). Provider: existing local Ollama with an explicitly pinned installed `llama3.2` or dense `qwen3` GGUF model and an application-owned raw template. This is a local single-principal experiment, not general backend support or custom KV injection. [Executed results](../evaluation/continuation-results.md) record successes, failed attempts and costs.

## Scope and owners

`tunic/render.py` validates current-snapshot IR, compacts it into a reversible evidence representation, emits exact source-to-rendered-span mappings and composes the fixed template. `tunic/ollama.py` owns loopback-only transport, model/server pin checks, exact backend token accounting, nontruncating execution and streaming metrics. `tunic/continuation.py` owns the fixed two-segment schedule, evidence exposure receipts and upfront/boundary comparison. The graph/extractor/query algorithm remain unchanged.

The renderer preserves all selected calls, paths, target definition, resolution support and coverage qualifications. It deduplicates identical source spans, assigns stable local citation labels, and maps them back to immutable source/IR identities. Each impact exposes its mechanically computed required citation list. JSON escaping/literalization changes presentation reversibly; it is not summarization. User tasks, source text and generated draft content cannot write native role delimiters. This does not establish semantic prompt-injection resistance. Source mappings are byte spans of encoded JSON literals, not per-source token offsets; this backend does not expose those token offsets.

## Budgets and execution

Render offline with an explicit UTF-8 byte limit; token count remains unavailable until a compatible backend counts the complete raw prompt. Do not call bytes “tokens.” The installed Ollama has no public tokenize endpoint and a probe with `num_predict=0` generated ten tokens rather than performing zero-output prefill. Therefore exact accounting uses an explicitly charged one-token inference probe, whose output is discarded. Record its full input/output work and latency; it is not cheap local tokenization, and an over-budget request can consume probe work before rejection. Reject a backend that exceeds the probe limit or cannot enforce nontruncation. Reject budget failure explicitly without dropping evidence or publishing an answer.

Pin server version, model manifest digest, model details/template metadata and Tunic template version. `truncate=false` and `shift=false` are required. Enforce actual input-token plus reserved-output bounds against configured context before generation; keep cache observations separate from input size. Check profile identity before execution and after the run. No model installation, remote endpoint, implicit fallback, provider credential or arbitrary executable tokenizer is needed.

Pin checks observe exposed server/model metadata before and after requests. They detect ordinary removal/replacement/version drift, but do not atomically lock an immutable model handle inside Ollama or rule out change-and-revert races. A changing profile invalidates the comparison; refresh installed models, repin and restart rather than substituting a new model in a running arm.

Llama 3 uses owned header/end-of-turn framing. The dense Qwen3 profile uses ChatML framing and a closed thinking prefix with explicit no-thinking execution. They are narrow manually supported formats, not a claim to reproduce every model's upstream template. See official [Ollama generation API](https://docs.ollama.com/api/generate), reviewed [request fields](https://github.com/ollama/ollama/blob/main/api/types.go), and [Qwen3 model instructions](https://huggingface.co/Qwen/Qwen3-4B). The recorded server/model digests and actual probes establish which local path was tested; current upstream documentation is not a substitute for capability checks.

## Experiment and acceptance

Both arms use the same task, pinned snapshot and exact evidence payload. Upfront compiles/renders before a model planning segment; boundary compiles/renders after that segment completes. The trigger is deterministic segment completion, not an inferred hidden state. The first segment is explicitly an ungrounded plan and is buffered as experimental output; only the final segment may answer from evidence. Final prompts differ in evidence placement and generated plan, so this is a schedule smoke comparison, not a controlled claim about latency/quality superiority.

Record graph/validation/render times, both complete prompt identities, original/escaped drafts, input/output tokens, probe-prefill and generation timings, first visible response latency, available cache counts and final answers. Missing counters remain unavailable. Exact-prefix reuse is not claimed merely because requests share text. No cache-off toggle, prefetch, tools, multi-tenant authorization, learned trigger or independent answer-quality judge is implemented in this increment.

Final generation uses an owned output schema. A separate gate accepts only known possible-impact symbols, their exact compiled witness paths and the full corresponding source-citation set. It rejects duplicate fields, unsupported identifiers/kinds, missing/extra citations and malformed output. This is selected-path support, not an independent correctness oracle for extraction or natural-language entailment. Supported subsets/abstention remain explicit, with missing compiler candidates reported. Raw model output is retained for inspection, even when rejected; it is not automatically a validated answer. Model-generated gap prose is not authoritative: the compiler's coverage diagnostics accompany the assessment unchanged.

Checks: reversible/deterministic rendering and citation/source mapping; reject stale/tampered IR; preserve coverage/unknowns; byte/token/context budget rejection; prevent evidence/task/draft from producing structural tokens; reject wrong model/server/profile, malformed or partial streams, overflow and backend probe-limit violations; fixed-snapshot attachment; fresh-process CLI and real local-model runs. HTTP fixtures test protocol handling only and are not inference evidence. Record actual model runs and limitations in evaluation documentation.
