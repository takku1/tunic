# W1 Python reference profile

Status: implementation profile for the first bounded vertical slice. It does not implement the full semantic graph contract or the V/G/T benchmark. See [overview](overview.md), [graph contract](semantic-graph.md), [IR](context-ir.md), and [workloads](../evaluation/workloads.md).

## Scope and ownership

`tunic/extract.py` captures Python source and static observations without executing repository code. `tunic/store.py` owns immutable SQLite source versions and atomically published full-rebuild snapshots. `tunic/compiler.py` owns reverse-call traversal, evidence-path compilation, and mechanical artifact validation. `tunic/__main__.py` exposes those operations as a CLI. The extractor profile is `python-static-v4`, which adds typed document claims (`depends_on`, `implements`, `supersedes`, `decided_by`, `contradicts`) from `tunic-claims` fenced JSON blocks to the former `python-static-v3` mention profile. Exact-key claims assert with `exact_key_match_v1`; names resolving to several entities become `proposed`/`proposed_ambiguous` rows, never merges. Reverse-call traversal admits `static_call` plus asserted `depends_on`/`implements` edges; proposals, mentions, and other relations never traverse.

This profile uses only Python's standard library. It accepts one local trusted repository per database and one explicit Python source root per snapshot. The graph profile itself implements no multi-user access boundary, valid-time history, inference engine, vectors, language model or runtime cache. A separate [continuation profile](continuation-reference.md) now renders its IR for local model execution. Snapshot history is transaction history, not real-world valid time. Retained source bytes are intentional local history; erasure is not implemented.

## Concrete semantics and choices

- Source identity is a relative POSIX path. Version identity hashes path and original bytes. Symbol identity is path plus top-level function name. Renaming is delete/add, not automatic identity resolution. Snapshot identity hashes the complete captured manifest plus extractor profile and coverage diagnostics; repeated unchanged ingestion is idempotent.
- Supported propositions are `static_call(caller, callee)`, asserted by the versioned extractor with exact call-expression byte evidence. These mean syntactically resolved possible calls, not demonstrated execution or transitive `calls`. Paths derive only `possible_impact` under a named reverse-reachability rule.
- Resolution covers unambiguous top-level functions, direct imports of functions, and module imports with aliases, including relative imports. Only unrebound names are eligible. Methods of undecorated top-level classes resolve under the same unambiguity rule via `self`/`cls`, `ClassName.method`, `ClassName().method`, and single-module imports; inherited methods, decorated classes, duplicate method names, dotted constructor bases, and nested classes remain gaps. Nested/class scopes beyond supported methods, star imports, dynamic dispatch, shadowing, and external calls are reported as gaps rather than guessed. Syntax/encoding failures retain source bytes but publish partial coverage. Symlinks are excluded. Scan/read failures abort publication.
- The whole captured repository is rebuilt before a single SQLite transaction publishes its snapshot, sources, entities, propositions/assertions, and coverage. Readers use one immutable snapshot; deletion removes current membership while retaining history. There is no incremental reuse certificate: every ingestion reruns extraction and every query recompiles. Filesystem capture is a best-effort scan, not an atomic filesystem snapshot; use an immutable checkout for a reproducible input.
- Queries take an exact symbol key and a finite depth/node bound. They return one deterministic shortest witness per reachable caller, including test functions by path/name convention. They report cycles/bounds and extraction limitations; no absence/completeness claim is inferred from this under-approximation.
- IR is canonical JSON with exact excerpts, source digests, scoped paths and a selection receipt. Each selected call includes its import binding (where applicable) and callee definition as resolution-support excerpts, so aliases are inspectable. Payload identity excludes machine paths/timestamps. Validation checks identity, snapshot membership, stored assertions, endpoint/path continuity, byte integrity and declared diagnostics against recompilation. It establishes mechanical support under this profile, not factual truth or behavior equivalence. Validation against a newer snapshot rejects stale artifacts explicitly.

## Delivery and acceptance

The selected write set is `tunic/`, `tests/`, `examples/`, architecture/status documentation, `README.md`, `pyproject.toml`, and `.gitignore`. No existing code or migration is required. Python/SQLite are reversible reference choices; other storage and richer resolution remain deferred. Model lowering is a separate bounded continuation increment.

Acceptance checks: independently expected cross-file/alias paths and misleading text exclusion; exact UTF-8 evidence; uncertainty for dynamic/shadowed calls; deterministic repeated ingestion and compilation; persistence across reopen; additions/edits/deletions versus fresh full recomputation; bounded traversal/cycles; rejection of corrupt/stale artifacts; interrupted publication rollback; real CLI ingestion/query/validation. Tests and observed results are recorded after execution. No performance superiority is assumed.

## Executed evidence

On Python 3.12.10, `python -m unittest discover -s tests -v` passes 49 tests exercising source-grounded paths, method resolution (`self`/`cls`, class-qualified, and constructor calls), document mentions with caller exclusion, typed document claims with proposal-not-merge ambiguity handling, UTF-8/CRLF/BOM coordinates, dynamic/shadowed/ambiguous calls (including global rebinding), syntax/encoding gaps, persistence, update replay against fresh databases, bounds/cycles, source/graph/artifact corruption, rollback, concurrent reader visibility, and CLI subprocesses. See [test source](../../tests/test_reference.py). The suite is correctness evidence for this profile, not an independently reproduced W1 benchmark.

The example CLI run ingested four source files and five symbols with two static-call assertions; its artifact identified the service and test callers and validated against the current snapshot. A separate CLI run ingested Tunic's own source tree and compiled/validated possible impacts for `tunic/identity.py::digest`. Both ran without executing analyzed source. These smoke checks establish a real local path through ingestion, SQLite persistence, compilation, and validation; answer-quality, model-token cost, and performance comparisons have not run.

## Blockers and limits

No blocker for this profile. The full-stack run guard cannot create its record under the session's read-only `.git`; verification uses direct commands and Git diff/status instead. This implementation run is unguarded. Remaining gaps are dynamic dispatch, inherited/decorated methods, natural-language claim extraction, doc-to-doc references, broader W1 coverage, a tuned dense-retrieval comparison, and W2/W3.
